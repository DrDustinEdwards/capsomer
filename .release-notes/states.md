# States pages are generated (what an app or a maintainer must know)

- `components/<name>/states.html` is no longer written by hand or committed. It is generated by `node bin/capsomer.mjs states` (`npm run states`) from `site/states-template.html`, the component's doc page (`title` becomes the `h1`, `summary` the intro) and `components/<name>/examples.html` (plus `examples.tsx` for React-rendered ones). The files are gitignored.
- A maintainer adds or edits a state in `examples.html`: only the `<section class="cap-specimen">` blocks and `<template data-specimen>` blocks, no `<html>`, `<head>`, `<main>` or `<h1>`. Loose `<link rel="stylesheet">` elements are moved to the head and loose `<script type="module">` elements to after the main. Details are in `components/README.md`.
- Generation runs by itself at the start of `npm run site`, `npm run site:release` and `npm run e2e`, in the Playwright web server command, and whenever `site/vite.config.ts` loads. Run `npm run states` to see the pages in a browser dev server.
- The URL of a states page is unchanged (`components/<name>/states.html`), so `visitStates` and the site's iframes are unchanged. The old intro sentences, which were hand-written, are replaced by each doc page's `summary`.
- React-rendered states (combobox, menu): `states.tsx` is now `examples.tsx`. knip and `tsconfig.build.json` are updated.
- `capsomer size` now also writes `test-results/size.json` (each component's gzipped CSS and JS, in bytes). Information only.
- No effect on an app that only installs Capsomer: states pages are not part of the package.
