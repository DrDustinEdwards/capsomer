## Threat model (STRIDE)

The package ships tokens, CSS, behaviour modules, and React wrappers to every app that installs it. The showcase site is a separate Worker: static assets plus one route that receives Content-Security-Policy reports. The thing it can get wrong is HTML or a URL built from caller data, a publish intent that clears the draft flag by mistake, or a workflow token that can push.

Who can call it: an app that imports the package; a person using the showcase site; GitHub Actions on pull request, push to `main`, a `v*` tag, and `workflow_dispatch`; Cloudflare Workers Builds, which deploys the site on every push to `main`.

Entry points:

- Library: the `exports` map. The ones every site can import include `capsomer/publish-transition`, `capsomer/email`, `capsomer/content`, `capsomer/behaviour/*`, `capsomer/react/*`, and the CSS entry points. `capsomer/testing` is the Playwright helpers.
- CLI: `capsomer` (`bin/capsomer.mjs`) builds states pages, site data, and the size, weight, and bloat reports. `git` is called with a fixed argument list.
- Worker: `worker/index.ts` for `/csp-report` only (`run_worker_first`). Every other path is static assets.
- Workflows: `ci.yml`, `ai-author.yml`, `pr-footer.yml`, `code-map.yml`, `no-bloat.yml`, `bump-consumers.yml`, `release.yml`.
- No MCP server, queue, or webhook. The showcase reads `results.json` from the `results` branch at runtime.

Where trust changes:

- Email HTML is escaped here, and `checkUrl` accepts only `https:` and `mailto:`. A URL with a username or password still passes (CM-2).
- System-map, chart-frame table cells, and draft-compare text are escaped. Chart SVG and stat-tile chart strings are documented as trusted markup.
- `draftForIntent` fails closed: an unknown intent stays a draft.
- Catalog enhancement fetches a same-origin, same-path response and swaps regions with `innerHTML`. A link to another origin is left to the browser. That check has no test (CM-6).
- The R2/D1/site data is the host app's. This package does not hold it.
- `main` is unprotected. The code-map job and the results job can push, and a release passes `RENOVATE_TRIGGER_TOKEN` (CM-1).

Spoofing: the showcase has no login. Theme and compare-view preferences are `localStorage` keys in the browser.
Tampering: `main` is unprotected (CM-1). Publish intents are a fixed table with a null prototype, so `constructor` is not a key.
Repudiation: the package writes no audit log. A host that publishes records that in its own store.
Information disclosure: the CSP report test locks that the query string and the blocked URL are not logged. Email values are escaped. The default dump of a site's content is the host's job.
Denial of service: one catalog response is parsed and swapped. The showcase fetches one `results.json`. There is no per-request D1.

- Area: 12. Supply chain
- Severity: MAJOR
- Confidence: confirmed by reading, by the GitHub API, and by the pinned devkit file at `27e0a1ca`. Not by a live runner.

A release, which this workflow starts when `package.json` changes on `main`, calls bump-consumers with `dry_run: false` and passes `secrets.RENOVATE_TRIGGER_TOKEN`. The tag `v0.10.0` still pins bump-consumers to `5fc5e5995612a3e48120f2122f9e7dfee7960365`. A push to this main uses `27e0a1ca`.
- Path: push a commit to `main` that changes `coverage-command` or `install`. The code-map job runs that shell with a token that can update `code-map`. Push a `package.json` version bump and the release job tags it and starts consumer bumps with the Renovate token.

## 10. Architecture and simplicity

The real structure: apps import CSS and, where a component does something CSS cannot, a behaviour module plus an optional React wrapper. `publish-transition` and `email` are pure and have no DOM, so a Worker can import them. The showcase is Vite, static assets, and a one-route Worker. Workflows call devkit. Site-runtime is used only to build the showcase headers.

`CLAUDE.md` and `components/README.md` describe that shape. The code matches it on the paths that were read: `enhance()` marks `data-cap-ready`, dynamic values go through `style.setProperty` in the behaviour modules that were read, and email colours are literal hexes because mail clients ignore custom properties.

Over-engineering: graduated pieces I would keep. The system-map seam router is a lot of geometry for one picture. It is tested, including a planted-fault check. I would not delete it.

Under-engineering: `checkUrl` is the link gate and it misses userinfo (CM-2). Four copies of the escape function. No Worker size budget. The Worker is one small module and `minify` is on. A budget would not change this deploy. I would add one when the Worker grows.

Shared code: this package is the shared copy. `capsomer/content` says the server half belongs in site-api and was written here until that kit shipped. The types are still defined here, with a comment that they should be reconciled with site-api. That split is unfinished. I would not copy the view types back into each app.
