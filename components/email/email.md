# Email templates

`capsomer/email` renders a mail to `{ subject, html, text }` from one template definition. A template is a list of typed blocks (heading, paragraph, button, code, note, fine print); `renderEmail` writes the HTML and the text from the same blocks, so they cannot disagree. It is pure: no dependency, no filesystem, no fetch, so it runs in a Worker, in Node and in a test. Sending stays with the product (the Cloudflare Email `send_email` binding); a send helper is not part of this.

## When to use it

Any transactional mail a product sends: a sign-in link, an address to confirm, a password reset, an alert, a plain notice, a change to how a person signs in.

## When not to

- **Bulk or marketing mail.** Foxhound's unsubscribe tokens and CAN-SPAM footer are its own; this module leaves a `footer` slot for the lines it supplies.
- **A page in a browser.** Email clients ignore custom properties, layers and container queries, so this layer shares the generator's colors but none of the components' CSS.

## The default and its reason

- **A single centered column, 600px at most,** nested tables with inline styles, system fonts, 16px body type, a button at least 44px high. It works at 320px with no horizontal scroll.
- **Light is the base.** Dark is best effort through `color-scheme` and `prefers-color-scheme`, with the same pairs from the dark scale; a client that ignores it still gets a readable light mail.
- **The brand is the product's name in type.** No logo image: nothing to host and nothing for a client to block.
- **Colors are the family's, as literal hexes** (`colors.ts`, generated by `tokens/palette.mjs`; `npm run check` refuses a file that differs). Text uses `text`, `muted` and `accent-text` (step 11, rule 18); the button fills with the primary (step 10) and carries `primary-fg`. The design note said step 9 for the fill; rule 18 (step 9 never carries text) wins. Every pair is one the token check already holds to 4.5:1 in both themes.
- **Meaning is never color alone.** An alert's level is a word in the subject and in the first line (Critical, Warning, Notice).
- **No tracking pixel and no click-tracking rewrite.** A token in a link is passed through untouched, and shown nowhere but in the one link (and, in the text part, on a line of its own).

## The templates

| Template | Takes | Says |
| --- | --- | --- |
| `magicLink` | `url`, `expiresIn`, optional `code` | who asked, works once, expires, ignore if not you; with `code`, the code to type into the page that asked, under the button |
| `verification` | `url`, `expiresIn` | the same, for confirming an address |
| `reset` | `url`, `expiresIn` | the same, for a password |
| `emailChange` | `step` (`current`, `new`), `url`, `expiresIn`; `newEmail` with `current` | to the current address: who asked, the new address, approve then confirm from the new one; to the new address: confirm to finish. When the link expires, never "once" (Better Auth's change links work until they expire); ignore if not you |
| `alert` | `level` (`crit`, `warn`, `info`), `what`, `when`, `details`, `url` | the level as a word, what and when, the detail lines |
| `notice` | `title`, `body`, `action` | a title and paragraphs, an optional button |
| `securityNotice` | `title`, `what`, `when`, `secure`, optional `device`, `location`, `url` | what changed and when, the device and place it came from when known, what to do if it was not them, a button to the account page; no link that signs in. site-runtime's `./sign-in` notice `detail` carries these fields |

Every template also takes `brand` (`{ name, family }`), `to`, and optionally `copy`, `footer` and `lang`.

```ts
import { renderEmail, magicLink } from "capsomer/email";

const { subject, html, text } = renderEmail(magicLink, {
  brand: { name: "Example Co", family: "purple" },
  to: "reader@example.com",
  url: "https://app.example.com/auth/verify?t=EXAMPLE-NOT-A-TOKEN",
  expiresIn: "15 minutes",
});
```

## How a product keeps its own copy

Capsomer owns the frame (layout, color, type, footer slot) and the default wording. A product passes `copy`, a partial object of strings (`subject`, `heading`, `intro`, `button`, `ignore`), which is escaped like any value; it cannot replace the frame or add markup. A product that needs another template defines one with the same block types (`Template<D>`) and gets the same frame, escaping and text part. It sends no raw HTML.

## Security

- Every value that reaches the HTML is escaped; a template author never concatenates a string into markup.
- A link is accepted only as `https:` or `mailto:`, with no space or control character. Anything else throws, and the throw is not to be swallowed.
- Single-line values (subject, brand name, `to`) are folded to one line, so none can add a header or a line.
- A fixture, a screenshot and a doc use an obviously fake token, `EXAMPLE-NOT-A-TOKEN`.

## Accessibility

- The document has a language, a title (the subject) and one `h1`; the button is a real link with a visible text label.
- Body and link text is 16px or more (the footer is 14px), and every text pair is in the contrast report for all three families in both themes.
