- **Breaking: offline keep's classes are `.cap-offline-keep-button` and `.cap-offline-keep-status`** (were `.cap-keep` and `.cap-keep-status`; `.cap-keep` also named the layout helper in `layout.css`, so a kept toggle took that helper's rules). The toggle keeps one label, "Keep on this device", and `aria-pressed` alone says it is kept (APG button: a toggle's name does not change); it no longer reads "Kept on this device" when pressed.
- **Related links: a site path is checked with site-runtime's `isSameOriginPath`, an address with `isHttpUrl`.** The own check let `/\t/host` through, which a browser reads as `//host`, so a stranger's address could render as an internal link without `rel`. **Removed:** `capsomer/behavior/related-links` (`httpHref`, `sitePath`, `longDate`); use `isHttpUrl` and `isSameOriginPath` from `@dustinedwards/site-runtime/url` and `<Time format="date">`. HTML contract: the date is `<span class="cap-related-date">` holding the shared `time.cap-time[data-format="date"]` (date-only `datetime`, the text color).
- **Removed: `countText` from `capsomer/behavior/pagination` and `capsomer/react/pagination`.** It copied content's; use `countText(shown, total, { noun, plural })` (or `nounsOf(labels, fallback)`) from `capsomer/behavior/content`. A zero total now reads "0 mentions", not "No mentions".
- **Breaking: `TablePanel` draws its table with `Table`.** It takes `caption` (visually hidden) and its children are the `thead` and `tbody`, no longer a whole `<table class="cap-table">`: move the caption's words to `caption` and drop the `table` and `caption` elements (Foxhound's admin-mcp-panels has three). The region stays named by the heading. A `Panel` with `href` now sets `aria-busy` while `reading`, as the section form does.
- **People and roles: a refused save says so.** A role change whose `onRoleChange` rejects puts the select back and says "Not saved" as a failure (it said "Saved" or nothing before), and with no `onRoleChange` a change says nothing until Save posts it. A rejected `onAccess` says the person could not be disabled or enabled. `RoleGrid` draws its region with the shared `Table`, and "Disabled" shows the date as `<Time format="date">` ("Disabled November 2, 2026", was the raw ISO day). New export `roleFailedText`.
- **One `PlainForm` and one `FormComponent`, in `capsomer/react/plain-form`.** Consent, the media inspector and row list drop their own copies. **Removed:** the `FormComponent` type from `capsomer/react/read-only-form` (import it from `capsomer/react/plain-form`; Foxhound's use-demo-guard does). `ReadOnlyForm`'s `form` defaults to `PlainForm` and no longer takes the string `"form"`; it is typed to take the `ref`. `RowForm["Form"]` is `FormComponent`, and `usePlainRowForm`'s form no longer defaults `method` to post (pass `method="post"`, as the attention list does).
- **Row list: a reply whose `onSend` rejects says so** (`failedHint`, "This was not sent. Your words are still here; try again.") and keeps the draft; before, the rejection went unhandled and nothing was said.
- **Player: the shared icons.** The controls draw `Icon` from `capsomer/react/icons` instead of their own SVGs, at the player's sizes and stroke (`--icon-size`, `--icon-stroke: 2` on `.cap-player-icon`). New icons: `iconFastForward`, `iconList`, `iconMute`, `iconPause`, `iconRewind`, `iconSkipNext`, `iconTimer`, `iconVolume`. **Removed** from `capsomer/react/player-controls`: `ChevronUpIcon`, `CloseIcon`, `AlertIcon`, `SpinnerIcon` (use `Icon` with `iconChevronUp`, `iconClose`, `iconAlert`, `iconSpinner`). The buffering spinner is `.cap-player-spin` on the icon itself.
- **Player: `PlayTrackButton` no longer sets `aria-pressed`;** its name ("Play X", "Pause X") already says the state (APG Button: one, not both). The play buttons carry `data-state="playing"` while playing, which the CSS reads instead of the label.
- **Breaking: the read-along transcript's container is `.cap-player-readalong`** (was `.cap-player-transcript`, which also names the transcript link line under a player, so the link's rules reached the read-along box and the box's grid reached the link line). Its cues take no tab stop (`tabIndex={-1}`); each paragraph's time button is the keyboard's way in. Search marks the query's words with the command menu's `markQuery`.
- **Menu: `chevron={false}`** leaves the trigger's chevron out, for an icon trigger that says what it opens; the player's sleep and chapters menus use it instead of hiding the chevron from outside.
- **Hooks: `useIsoLayoutEffect`** from `capsomer/react/hooks` (useLayoutEffect in the browser, useEffect on the server), replacing three local copies in the player and poll.
- Player: the clip wave's pulse uses `--dur-wait`; a refused clip play is reported with `reportError`, no longer thrown from the promise.
- **Breaking: `PlanChoice`'s options are the field's card choice.** Each plan is `label.cap-check[data-variant="card"]` with its radio first and `span.cap-plan-option-text` holding `.cap-plan-option-name` and `.cap-plan-option-price`; **`.cap-plan-option` is removed** (it copied the card check). A page that writes the markup by hand loads `field.css`.
- Poll: the share bar grows with `transform: scaleX()` from the start edge, no longer by animating `inline-size`. The forced-colors rules of poll, price card and process sit inside `cap.components`.
- **Prose: the heading tokens live in `css/prose.css`.** `--prose-heading-face`, `--prose-heading-space`, `--prose-h2-size` and `--prose-h3-size` are read where the heading face, space and sizes are set, so `prose-blocks.css` no longer sets them a second time; the values are unchanged. **Removed:** prose blocks' `.reading-progress` rules (Prelum's render/enhance draws `.cap-reading-progress`, the reading-progress component, since Prelum's breaking change).
- **QR: `size="lg"`** on the React `Qr` sets `data-size="lg"`, the 10rem size the CSS and doc page already had.
- **Range slider: a press on the track sets the nearer handle** (WCAG 2.5.7, a single pointer with no drag), in the behavior module and `RangeSlider`; new export `trackPick`. The fill runs from the right on a right-to-left track. DEFAULTS.md's refused-patterns row records Dustin's ruling (2026-11-13) that the range slider is built, and how it meets WCAG 2.5.7 and the APG Multi-Thumb Slider.
- Rating: `RatingInput` draws its select with the shared `Select` (`native`); the wrapper is now `div.cap-select-wrap[data-cap="select"][data-native]` (was a `span`).
- **Repeater field: rows keep their keys with the sortable list's `useRows`,** move with `moveId` and are announced in `sortText`'s words ("Added Link 4. 4 in the list.", "Moved Link 2 to position 1 of 3.", "Removed Link 2. 2 left."). **Removed:** `moveRow` and `changeText` from `capsomer/behavior/repeater-field`; use `moveId` and `sortText` from `capsomer/behavior/sortable-list`.
- **Rich editor: two editors on one page keep their own ids.** The image step's alt field and help and the link palette's field, listbox and options were fixed ids (`rich-alt`, `rich-link`, ...), so a second editor's labels and `aria-activedescendant` pointed into the first; they are prefixed with `useId()`. The block menu and link palette open with the popover's `openAt` (re-placed on scroll at the caret), and the toolbar and block menu arrows use toolbar's `rovingIndex` (right-to-left aware).
- **Fix: rich text field reads only its own entity names.** `&constructor;` or `&toString;` decoded to a function's source text (the name table is a plain object); they now stay as written. Ctrl or Cmd+I is blocked in a field that does not allow `em`, as B and U already were, so the browser's italic never shows what the value drops.
- **Route hooks: `useScrollToHash` survives a malformed hash** ("#%E0" threw inside the frame callback; the hash is now read as written). **Removed:** the re-export of `filterParams`, `pagePending` and `withParam` from `capsomer/react/route-hooks`; import them from `capsomer/behavior/form-hooks` (no consumer imported them from route-hooks).
- **Save toggle keeps one label.** The button no longer switches "Save" to "Saved" while it also sets `aria-pressed` (a screen reader heard "Saved, toggle button, pressed"); the pressed chip and filled bookmark show the state. **Removed:** `SaveToggle`'s `savedLabel` prop and the behavior's `data-saved-label` and `data-label`.
- Scale control: the units select sits in the shared `Field` (its id from `useId`, so two controls on a page no longer share `${name}-${units.name}`), and the submit is the shared `Button`.
- Schedule: the day links take the shared focus ring (focus.css) in place of their own 3px ring at a 1px offset. The slot's `<time>` markup is built from `slotParts` (new export: the words and the moments they name), which `slotLabel` joins, so a change of wording can no longer break it.
- **Schedule dialog: each opening starts from `current`.** The dialog stays mounted while closed, so reopening it for another item showed the last item's time. Its status line is on the page from the start and filled, so the first time chosen is announced. **Removed:** `localValue` from `capsomer/behavior/schedule-dialog`, and `localInputValue` and `isoFromLocal` from `capsomer/behavior/posts-list`; use `toDateTimeLocal(date, zone)` and `fromDateTimeLocal(value, zone)` from `capsomer/behavior/field` with the browser's zone.
